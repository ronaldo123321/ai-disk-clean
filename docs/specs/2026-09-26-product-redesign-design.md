# 清理大师产品重构设计

日期：2026-09-26
状态：已与用户逐节确认
取代：`2026-09-17-disk-cleaner-design.md` 的产品与交互部分、`2026-09-19-evidence-model-design.md` 全部。安全底层（第 5 节禁区、路径防护、恢复区）继续有效。
依据：`../v2/21-真机手动清理复盘与需求.md`

## 1. 定位

面向公司内部重度使用 AI 的员工：iOS、Java、Python、TypeScript 开发，测试、产品、运营。各角色常用软件不同，AI 工具高度重合（Claude Code、Codex、Cursor、WorkBuddy、龙虾、Qcoder、豆包、千问、Trae 等）。

| 维度 | 决定 |
|---|---|
| 平台 | 首版只做 macOS；平台相关代码隔离在协议之后，为 Windows 留路 |
| 形态 | 纯个人工具。无服务端、无上报、无集中管理 |
| 核心场景 | 满了能救急 + 平时有提醒。「看清 AI 工具存了什么」只作辅助 |
| 自动化 | 日常：提醒时给出方案，确认一次即执行。可选：安全档自动清理，默认关闭 |
| 规则之外 | 大目录只展示不清理；用户可加自定义规则；可一键复制匿名说明反馈给维护者 |
| 首版覆盖 | AI 工具、开发工具、浏览器、常用办公软件。用户自己的文件（下载、视频、录屏）不在首版 |

成功标准：用户一次确认腾出可观空间；结果页的实际释放与预估一致或解释得清；无误删工作资料、会话、凭据。

## 2. 核心概念

### 2.1 清理项

界面展示的最小单位，例如「npm 缓存 8.1G」「Chrome 网站缓存 19G」「项目 central-intelligence 的依赖 2.1G」。每项必须给出：

- **是什么**：一句大白话
- **删了有什么影响**：如「下次装包要重新下载」
- **能否找回**：移入恢复区的可还原；工具自带命令清理的不可还原但可重新下载
- **当前能否处理**：如「需要先退出 Chrome」「被 chroma-mcp 占用」

### 2.2 四档

| 档位 | 例子 | 默认 | 可自动清理 |
|---|---|---|---|
| 安全 | 包管理器缓存、构建缓存 | 进方案并选中 | 用户开启后可以 |
| 建议 | 闲置项目依赖；需先退出应用的缓存（浏览器、IDE、办公软件） | 进方案并选中，标注需退出的应用 | 不可 |
| 需要确认 | Docker 镜像、AI 工具旧版本与日志、用户自定义规则、未经实测的国产 AI 工具 | 列出，默认不选 | 不可 |
| 只展示 | AI 会话记录、数据库、规则之外的大目录 | 只显示大小 | 永不 |

硬编码禁区（系统目录、`~/Documents`、`~/Desktop`、`~/.ssh`、`.git` 等，沿用现有 `ProtectedLocations`）不出现在任何档位，也不在空间分布中展开。

档位由规则直接声明，不再由证据强度推导。执行时的动态条件（应用是否运行、是否被占用、项目闲置天数）只能把一项**降级**为当前不可处理，不能升档。

### 2.3 清理方案

一次提醒或一次救急对应一份方案：按档位汇总清理项，给出预估可释放量（按 inode 去重，扣除硬链接共享），用户确认一次即执行。

### 2.4 恢复区

除工具自带命令外，所有清理项先移入工具自管的恢复区（与被清理目录同卷，移动为 rename），不使用系统废纸篓。理由：工具可统计、可还原、无需 `~/.Trash` 的访问授权。默认保留 7 天，到期提醒清空；用户可开启到期自动清空。

### 2.5 规则包

内置规则随应用更新；用户自定义规则存于独立文件，更新不覆盖。

## 3. 交互

### 3.1 菜单栏弹窗（主入口）

显示：磁盘占用与可用、本周增长及主要来源、推荐方案（可释放量、各档项数、需退出的应用）、「一键清理」按钮、「查看详情」、恢复区占用。

### 3.2 主窗口：单页方案

- 顶部：磁盘总览、本周增长；右上角入口：恢复区、设置
- 顶部切换：**按档位** / **按应用**。按应用列出每个软件（Chrome、uv、Docker、Claude、Cursor…）的合计占用，展开为其清理项
- 主体：按档位分组，可展开，组与项均可勾选；「只展示」组显示规则之外的大目录，提供「在 Finder 中显示」「加为我的规则」「复制反馈」
- 底部固定：「清理已选 X G」

### 3.3 执行流程

1. **执行前复核**：逐项重新检查目标存在、占用、应用运行状态。状态变化的项跳过并记录原因
2. **集中退出应用**：一个页面列出需退出的全部应用。「帮我退出」先正常退出；10 秒未退出的，由用户逐个选「强制退出」或「跳过此项」，不会自动强制退出。IDE 只提示「请先保存再退出」，不提供代为退出。用户也可选择只清不需退出应用的项
3. **暂停占用服务**：仅对规则中登记为「可安全暂停」的服务，执行「暂停 → 清理 → 恢复 → 健康检查」，三步在一次执行内连续完成，防止被 hook 等重新拉起。未登记的占用者一律跳过该项
4. **结果页**：
   - 实际释放：执行前后卷可用空间差值
   - 恢复区待清：清空后还能再腾出多少
   - 跳过项及原因
   - 会自动长回来的项及关闭方法（如 Chrome 本地模型 → `chrome://flags`）
   - 外部变化：与工具操作对不上的空间变化单独标注，不计入工具成果

### 3.4 平时提醒与自动清理

- 常驻菜单栏，登录时启动，每天后台只读扫描一次
- 提醒条件（任一）：可用空间 < 10%；可释放量 > 10G；近 7 天可用空间减少超过 20G
- 同一条件触发后 24 小时内不重复提醒
- 自动清理开启时，只执行安全档中无需退出应用、未被占用的项；结束后菜单栏显示「已自动腾出 X G」

## 4. 架构

四层，自下而上：

### 4.1 平台层（Windows 版唯一需要重写的层）

保留：`FileOperations`、`SafeDirectory`、`ProcessRunner`、`GuardEvaluator`。
新增：应用控制（是否运行、正常退出、强制退出）、服务暂停与恢复、卷可用空间读取。
全部以协议暴露，上层不直接依赖 macOS API。

### 4.2 安全层（保留，小改）

- `PathSafety`、`ProtectedLocations`：不变
- `Quarantine` → `RecoveryStore`：7 天保留、占用统计、到期清空
- `AuditLog`、`OperationLease`：不变

### 4.3 引擎层（重写）

**RulePack**：JSON。每条规则字段：

| 字段 | 含义 |
|---|---|
| `id`、`app`、`category` | 规则标识、所属应用、类别（ai / dev / browser / office；空间分布的未识别项为 other） |
| `tier` | safe / suggested / confirm / displayOnly |
| `detect` | 应用是否安装的判断（bundle id、可执行文件、路径存在） |
| `targets` | 路径模板，按平台区分 |
| `action` | `command`（工具自带命令）/ `recover`（移入恢复区）/ `recoverOlderThan`（仅超过 N 天的条目） |
| `preconditions` | 需退出的应用、锁文件、可安全暂停的服务 |
| `copy` | 是什么、影响、是否会自动长回来及关闭方法 |

校验：`command` 只能配 safe 或 confirm（命令不可还原，不得作为默认选中的建议档；Docker 镜像这类命令动作放需要确认档）；用户自定义规则只能用 `recover` / `recoverOlderThan`、档位固定为 confirm；任何目标不得命中禁区。

**Detector**（四种，产出清理项）：

1. 规则扫描：按 RulePack 匹配已安装应用的目标
2. 项目产物：`node_modules`、`.venv`、`venv`、`target`、`build`、`dist`、`.next`、`Pods` 等。按最后活跃（`.git/logs/HEAD` 记录的最近一次 HEAD 变动、`.git/index` 与源码修改时间取较新；不对用户仓库运行 `git log`，`git status` 仅在仓库未配置本地过滤器时运行）分档：≥90 天 → 建议，30–90 天 → 需要确认，<30 天 → 不产出。`build` / `dist` / `coverage` 仅在同级有工程标记文件时识别。排除隐藏工具目录、`.app` 内部、IDE 扩展目录。无 lockfile 的降为需要确认。项目有未提交改动时提示但不影响档位
3. Docker：仅当 daemon 已运行时通过 docker 命令识别，不替用户启动 Docker。按容器状态与卷分开判断；compose 镜像按 ID 而非 `repo:tag` 判断是否在用；扩展容器（不在 `docker ps -a` 中）引用的镜像视为在用
4. 空间分布：规则之外的大目录，只产出只展示项

**Sizer**：同时计算表观大小与预估可释放量（按 inode 去重，`st_nlink > 1` 的文件只在全部链接都在清理范围内时计入）。

**Planner**：清理项按档位与用户勾选生成方案。

**Executor**：复核 → 集中退出应用 → 暂停/清理/恢复服务 → 测量前后可用空间 → 结果。

### 4.4 界面层（重写）

SwiftUI 菜单栏应用，登录项启动，内部定时扫描，不设独立后台进程。页面：菜单栏弹窗、主窗口（单页方案，按档位/按应用切换）、执行确认与退出应用页、结果页、恢复区、设置（自动清理、恢复区自动清空、自定义规则、复制匿名反馈）。

`dclean` CLI 保留，用于调试与开发者使用。

### 4.5 移出首版

`Evidence`、`V2Policy`、`Staleness`（以 `recoverOlderThan` 取代）、`ClaudePluginInventory` / `Preview` / `Preflight`、`CursorWorkspaceInventory`、`CodexSessionInventory`、`ProjectReferenceParser`、`ReferenceReachability`、`VersionRedundancy`、`BoundedMetadataReader`。代码保留在 git 历史，日后「看清 AI 工具」辅助场景需要时改造为 Detector。

## 5. 首版规则覆盖

| 类别 | 覆盖 |
|---|---|
| AI 工具 | Claude Code 与 Claude 桌面端、Codex、Cursor、WorkBuddy、龙虾、Qcoder、豆包、千问、Trae |
| 包管理器 | npm、pnpm、yarn、bun、pip、uv、Poetry、conda、Homebrew、Gradle、Maven、CocoaPods |
| IDE 与构建 | JetBrains 系列、VS Code、Xcode（DerivedData、模拟器、iOS DeviceSupport） |
| 项目产物 | 见 4.3 Detector 2 |
| 容器 | Docker |
| 浏览器 | Chrome、Edge、Safari 缓存 |
| 办公软件 | 飞书、钉钉、微信、企业微信 |

WorkBuddy、龙虾、Qcoder、豆包、千问的数据位置与可清理性缺少可靠资料，首版一律为需要确认档；经真机实测后再调整。空间分布与匿名反馈用于收集这些数据。

## 6. 错误处理

- 单项失败只影响该项，不中断方案；原因写入结果页与审计日志
- `command` 失败不回退为自行删除
- 移入恢复区失败的保持原状
- 服务恢复后健康检查失败，结果页明确提示并给出手动恢复方法
- 扫描中权限不足的目录标为「无法读取」，不猜测大小

## 7. 测试

- 平台层与安全层：保留现有测试
- 引擎层：`InMemoryFileOperations` 与 `FakeProcessRunner` 驱动的单测，覆盖分档、inode 去重、复核降级、退出应用编排、暂停/恢复原子性
- 规则包：对每条内置规则断言目标不命中禁区、`tier` 与 `action` 组合合法、文案字段齐全
- 真机只读验收：只扫描不执行，在不同角色同事的机器上运行

## 8. 交付拆分

每个子项目单独走设计细化 → 实施计划 → 实现：

1. **引擎重构**：RulePack 新格式、四种 Detector、Sizer、Planner、Executor；CLI 可用并可做真机只读验证
2. **界面**：菜单栏弹窗、主窗口、执行与结果页、恢复区
3. **提醒与自动清理**：每日扫描、提醒条件、安全档自动清理
4. **规则扩充**：办公软件与国产 AI 工具规则、自定义规则、匿名反馈
