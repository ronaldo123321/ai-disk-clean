# 证据模型重构 · 设计文档

2026-09-19｜已获用户逐段确认｜取代现有红黄绿风险字段

## 1. 背景与问题

### 1.1 目标人群转向

产品定位从「macOS 办公与开发用户」收窄为 **AI coding 重度使用者**，处理 AI 工具链产生的垃圾。

### 1.2 现状测量（2026-09-19，开发者本机）

整盘 460.4 GB，已用 419.2 GB。现有 17 条规则覆盖 78.2 GB（已用空间的 18.7%），其中：

- 🟢 21.7 GB 命令委托（uv 缓存占 21.1 GB）
- 🟡 628 MB 可移废纸篓
- 🔴 55.9 GB 只读展示

AI 工具实际占用约 43 GB：

| 位置 | 大小 | 覆盖状态 |
|---|---|---|
| `~/.cache/uv` | 21 GB | 命令委托 |
| `Cursor/User/globalStorage` | 9.5 GB | **完全未覆盖** |
| `~/.codex/sessions` | 4.6 GB | 红色只读 |
| `~/.claude/plugins/cache` | 2.8 GB | 红色只读 |
| `~/.codex/skills` | 2.1 GB | 未覆盖 |
| `.codex` 的 sqlite 文件 | 2.5 GB | 未覆盖 |
| `Cursor/User/workspaceStorage` | 1.1 GB | 未覆盖 |
| `ms-playwright` | 628 MB | 可处理 |

### 1.3 安全论证的断点

现有模型把**「有官方 CLI 可委托」当作唯一的强证据来源**。Cursor 的 globalStorage、codex sessions、插件缓存这些最大头的数据没有官方清理命令，在现有框架里永远只能是红色。

同时 `Rule.risk` 是**手写字段**，与实际证据脱节。`V2Policy.apply` 把所有规则强制设为 `.red` 正是这一脱节的体现——安全性靠外部补丁维持，而非由规则自身论证。

### 1.4 关键观察

现有适配器**已经在做「证据推导风险」**，只是没有形式化：

- `PlaywrightAdapter` 找到 `INSTALLATION_COMPLETE` 才给 `.yellow`，否则 `.red`
- `UVAdapter` 版本在 `testedVersions` 内才给 `.green`
- `Rule.adapterEvidence: String?` 字段已存在，但只是展示字符串，引擎不消费

因此本次重构不是推倒重来，而是**把适配器里已在运行的隐式逻辑提升为一等公民**。

## 2. 核心模型

### 2.1 拆开两个正交维度

当前 `risk` 字段压缩了两件本应分离的事：

- **可不可以动** —— 取决于证据强度
- **怎么动才安全** —— 取决于动作能否回滚

正因为耦合，才需要 `Strategy.isCompatible(risk:type:)` 这条手写规则打补丁。新模型：

```
证据采集 ──> Evidence[] ──> EligibilityEvaluator ──> 处理资格 + 证据强度
                                                          │
                              Strategy ──> Action ────────┴──> 可逆性校验
```

### 2.2 资格推导矩阵

| 证据强度 | 动作可逆 | 结果 |
|---|---|---|
| 强（版本冗余 / 引用不可达 / 工具权威） | 可逆（移废纸篓） | 推荐处理 |
| 强 | 不可逆（命令 / 直接删除） | 需要确认 |
| 弱（仅陈旧度） | 可逆 | 需要确认 |
| 弱 | 不可逆 | **引擎层面不可表达** |
| 无证据 | — | 只读展示（附「缺什么证据」） |

**倒数第二行是不变量，不是提示**：弱证据配不可逆动作在引擎里根本无法构造。这使「强制可逆」成为类型层面的保证，而非文档约定。推论：陈旧度证据永远不能驱动 `uv cache prune` 那类命令，即使将来某个工具的命令看起来很安全。

现有 `Strategy.isCompatible(risk:type:)` 从公理降级为本不变量的推论，删除。

**本矩阵会改变现有行为，须留意**：命令委托是强证据但不可逆，落在第二行，因此 uv 与 Homebrew 从当前的「🟢 推荐清理」变为**「需要确认」**。这是刻意的——`brew cleanup -s` 会删除已安装包的旧版本且不可还原，与 PRD §3 对「推荐」的定义（低影响、边界确定）不符，更符合「需要确认：有明确操作能力，但重建成本需要用户决定」。二者本就默认不选，实际交互变化很小。

### 2.3 只读状态的语义变化

现在 11 条红色规则是因为**有人手写了 `.red`**；新模型下只读是**证据采集返回空**的结果，并且能具体告知缺失的证据类型。`V2Policy.apply` 中强制 `.red` 的迁移 hack 随之删除（`diagnostic-reports` 的规则改写特例保留，那是真实的规则覆盖而非 risk hack）。

## 3. 证据采集器

统一约定：**采集失败 = 无证据 = 只读**，绝不假定无问题（失败关闭，与现有 `ProtectedLocations` 一致）。

每个采集器都是对文件树的纯函数，可在扫描期与 apply 期各跑一次，接入现有 Executor 两段式复核。

### 3.1 `versionRedundancy`（强）

**判定**：同级存在 ≥2 个可解析版本 ∧ 候选不是最新 ∧ 候选无「在用」标记。

版本族提取器（每工具一个）：

| 工具 | 版本族结构 | 实测 |
|---|---|---|
| Claude 插件 | `cache/<市场>/<插件>/<版本>/` | `thedotmack/claude-mem` 6 个版本，2.8 GB |
| Playwright | `ms-playwright/<名>-<构建号>` | chromium-1187 / 1208 |
| Puppeteer | `<浏览器>/<平台>-<版本>` | 现有适配器已实现 |

**实现陷阱（实测得出，非通用模板）**：

1. **版本比较必须按数字分段**。字典序下 `5.0.7` > `5.0.10`，会导致删除真正的最新版。
2. **`.in_use` 与 `INSTALLATION_COMPLETE` 语义方向相反**。前者表示「正在使用」，出现即排除；后者表示「安装完整」，出现才纳入。不可套用同一判定。

### 3.2 `referenceUnreachable`（强）

**判定**：指涉路径为绝对路径 ∧ 该路径不存在 ∧ **其所在卷已挂载**。

第三个条件是安全底线：外接盘上的项目不得因未挂载而被判为孤儿。卷未挂载时采集器弃权。

| 工具 | 指涉来源 | 实测 |
|---|---|---|
| Cursor 工作区 | `workspaceStorage/<hash>/workspace.json` → `.folder`（file:// URL） | 25 个，2 个失效 |
| Codex 会话 | `rollout-*.jsonl` 首行 `payload.cwd` | 481 个，1 个孤儿 |

### 3.3 `staleness`（弱 → 强制可逆）

**判定**：解析出的日期早于阈值。阈值取规则自身的 `strategy.olderThanDays`，Codex 会话规则定为 **90 天**（实测：481 个会话中 102 个超过 90 天，占 1.02 GB）。证据须记录**日期来源**：

- `.pathEncoded` —— 从 `sessions/YYYY/MM/DD/` 目录结构解析，可信
- `.modificationTime` —— 回退到 mtime，明显更弱（备份、同步、`touch` 均会改写）

两种来源都触发强制可逆，但来源须记入证据并在界面如实展示——弱点要可见。

现有 `glob-age` 的 `olderThanDays` 继续作为**过滤条件**存在，但过滤不等于证据：诊断报告可被处理是因其本身是可重建的过程产物，而非因为它旧。

### 3.4 `toolAuthority`（强）

**补充记录**：本类型是写实施计划时发现的缺口。把现有 4 个适配器的依据逐一映射到 §3.1–3.3 时，发现**没有一个能落进去**——严格执行会导致 Playwright / Puppeteer 退回只读，属功能倒退。

**与已排除的「工具自声明为 cache」的区别**：后者是靠目录命名猜测（路径里有 `Cache`/`CachedData` 就认为能删）。本类型要求**工具自身产出的可核验凭据**——命令输出，或工具亲手写入的标记文件。二者强度差距很大，提问时被我合并成一个选项，是提问的疏漏。

**三种依据**：

| 依据 | 含义 | 适用 |
|---|---|---|
| `enumeration` | 工具公开接口枚举出的具体路径 | pip `cache list --format=abspath` |
| `cleanupCommand` | 官方清理命令负责判定与执行 | `uv cache prune`、`brew cleanup -s` |
| `installationMarker` | 官方布局 + 工具写入的完整性标记，且有官方下载源 | Playwright `INSTALLATION_COMPLETE`、Puppeteer 官方布局 |

**判定**：工具版本在适配器的 `testedVersions` 内 ∧ 凭据可复现获取（命令可重跑、标记文件仍在）。版本未验证或凭据获取失败 → 弃权，转为只读。这与现有适配器的行为完全一致，本类型只是把它形式化。

`installationMarker` 隐含依赖可重建性（删掉后工具会重新下载）。这是唯一保留的可重建性用法，且被严格限定：必须同时具备官方标记与官方下载源，不接受「看起来像缓存所以能重建」。

## 4. 与现有引擎的接合

### 4.1 序列化兼容

| 产物 | 处理 |
|---|---|
| `report.json` / `last-plan.json` | **不做兼容，直接换格式**。二者是瞬时产物，计划有 15 分钟过期 + `rulesFingerprint` 校验，旧格式会被现成机制拒绝 |
| `rules.json` | 用户文件，不得损坏。`Rule.risk` 保留为**可解码的遗留字段，解码后忽略** |

已确认可接受的代价：升级后若手上有未执行的计划，会被拒绝并要求重新扫描。

### 4.2 调用点改动

| 位置 | 现在 | 改为 |
|---|---|---|
| `Planner` | `if rule.risk == .red { continue }` | `if eligibility.isDisplayOnly { continue }` |
| `Planner` | `action = risk == .yellow ? .quarantine : .delete` | 由证据强度 + 可逆性推导 |
| `Executor` | `rule.risk != .red`、`item.risk == rule.risk` | eligibility 等价校验 |
| `Models.swift` | `Strategy.isCompatible(risk:type:)` | 删除 |
| `ReportEntry` | `adapterEvidence: String?` | `candidateEvidence: [String: [Evidence]]` |

最后一项沿用现有 `candidateSizes` 的逐候选字典形态；展示文案由结构化证据渲染，不再手写字符串。

**迁移面实测**：`risk` 在 12 个源文件 38 处引用，10 个测试文件 67 处断言。

### 4.3 Executor 必须重采集证据（安全关键）

现有两段式复核只校验路径存在性、禁区、围栏与身份快照，**证据不在其中**。必须新增：apply 前重跑采集，证据消失即跳过该条。

场景：预览时某 session 的项目目录已删（孤儿证据成立），用户在确认前从 git 恢复了该项目——证据此刻不再成立，该条必须自动跳过。这与现有 TOCTOU 跳过同类，接在同一位置。

### 4.4 新增文件

`Models.swift` 已 483 行，证据体系不再向其中追加：

- `Evidence.swift` —— 证据类型、资格、`EligibilityEvaluator`
- `VersionRedundancy.swift` / `ReferenceReachability.swift` / `Staleness.swift` —— 三个采集器各自独立、纯函数、可用 `InMemoryFileOperations` 单测

相对现状的实质改进：现在 Playwright 的标记检查埋在适配器内部，只能靠集成测试覆盖；拆出后可用假文件树精确测试边界条件。

## 5. 本轮范围

### 5.1 交付

**内核**：`Evidence` / `Eligibility` / `EligibilityEvaluator` + 三个采集器。

**迁移**：现有 5 个适配器（pip、uv、Homebrew、Playwright、Puppeteer）改为产出结构化证据。外部行为不变。

**新增规则**：

| 规则 | 证据 | 动作 | 预期产出 |
|---|---|---|---|
| Claude 插件旧版本 | 版本冗余（强） | 移废纸篓 | ~2.3 GB |
| Codex 孤儿会话 | 引用不可达（强） | 移废纸篓 | 3 MB |
| Codex 陈旧会话 | 陈旧度（弱） | 强制移废纸篓 | ~1.02 GB |
| Cursor 失效工作区 | 引用不可达（强） | 移废纸篓 | 0 MB（随时间增长） |

新增合计约 3.3 GB。

### 5.2 分阶段

迁移面较大（38 处源码引用 + 67 处测试断言），按项目既有惯例分两阶段，每阶段独立可验收：

**阶段一 · 内核与迁移（行为保持不变）**

交付 `Evidence` / `Eligibility` / `EligibilityEvaluator` 与三个采集器，把现有 5 个适配器改写到内核上，替换 `risk` 的全部调用点。

验收标准（写计划时细化，原表述不够精确）：

**不变量——安全相关，必须逐条断言**：

- 能进入计划的规则集合不变（不得有规则新获得或失去可处理性）
- 每条规则的 `PlanAction` 不变（quarantine 仍是 quarantine，command 仍是 command）
- 现有 159 个测试全部通过，67 处 `risk` 断言改写为 eligibility 等价断言，**语义不得放宽**

**会变化——展示层，属预期**：五条规则的资格标签按 §2.2 矩阵重新推导：

| 规则 | 现在 | 之后 | 原因 |
|---|---|---|---|
| pip-cache | 需要确认 | 推荐 | 工具权威（枚举）+ 可逆 |
| playwright / puppeteer | 需要确认 | 推荐 | 工具权威（标记）+ 可逆 |
| uv-cache / homebrew-cleanup | 推荐 | 需要确认 | 工具权威（命令）+ 不可逆 |

**必须同步修改 GUI，否则是回退**：`ContentView.category()` 目前只把 `.yellow` 映射到「需要确认」，**`.green` 没有任何分支**，会落到「暂不可处理」——这是既有缺陷（uv/brew 在 GUI 里显示为暂不可处理，CLI 却能正常计划）。改为 eligibility 后若不同步更新该函数，新获得「推荐」资格的 pip/playwright 会从界面上消失且无法勾选。

这一阶段不新增任何可清理内容，价值在于建立可单测的证据基座并移除 `V2Policy.apply` 的 `.red` 补丁。

**阶段二 · 新增 AI 工具规则**

在已验证的内核上加四条新规则（见 §5.1 表格），逐条走真实数据闭环验证。

这样拆的理由：阶段一是纯重构，有现成的 159 个测试作回归网，风险可控；阶段二才引入新的删除能力，此时证据模型已被阶段一验证过。两者混在一起做，会让「测试失败是重构引入的还是新规则引入的」难以区分。

### 5.3 明确不做

| 项目 | 大小 | 原因 |
|---|---|---|
| `state.vscdb.backup` | 3.7 GB | 形态符合版本冗余，但它是 Cursor 的崩溃恢复副本。删除等于移除活动库损坏时的退路，收益与代价不匹配。**只读展示，如实说明占用与用途** |
| `state.vscdb` | 4.9 GB | 活动数据库，本轮不做库内操作 |
| `~/.codex/skills` | 2.1 GB | 实测为扁平结构，无版本目录，三类证据均不适用 |
| `.codex` sqlite 文件 | 2.5 GB | 单个活动库文件，同上 |

四项合计 13.3 GB 保持只读。新模型的价值在于其只读状态是**推导所得且能说明缺失证据**，而非手写 `.red`。

### 5.4 未来可选方向（本轮不做）

- 库内修剪动作类型（需要全新安全论证：备份、完整性校验、工具未运行确认）
- 更多 AI 工具适配（Windsurf、Zed、Continue 等）
- 可重建性 / 工具自声明为 cache 两类弱证据（本轮经讨论排除）

## 6. 测试策略

1. **采集器单测**（新增，`InMemoryFileOperations` 假文件树）——必须覆盖三个陷阱：数字版本比较（`5.0.7` vs `5.0.10`）、`.in_use` 反向语义、卷未挂载时弃权
2. **资格矩阵穷举**——证据强度 × 可逆性全组合；「弱 + 不可逆」须在构造期即不成立
3. **Executor 证据重采集**——计划生成后指涉对象恢复 → 该条跳过
4. **现有 159 个测试全部保持通过**——它们编码现有安全契约，是本次重构的回归网。67 处 `risk` 断言改写为 eligibility 等价断言，**语义不得放宽**
5. **真实数据闭环**——选一个新规则跑 扫描→计划→执行→还原，逐字节核对（沿用 2026-09-18 验证 pip-cache 的方法：sha256 基线 + 还原后逐项比对）

## 7. 决策记录

本设计经逐项确认：

| 决策 | 选择 |
|---|---|
| 会话历史定位 | 分层：近期是资产，陈旧是垃圾 |
| 证据词汇表 | 版本冗余 + 引用可达性（排除「目录名像 cache」式的猜测） |
| 工具权威（第四类） | 写计划时发现的缺口，补入。要求工具自身产出的可核验凭据 |
| 陈旧度 | 追加为第三类证据，但强制可逆 |
| 数据库类数据 | 本轮只做库级文件，不进库内 |
| 与现有规则关系 | 重构：证据分级取代红黄绿 |
| 旧 report/plan 兼容 | 不兼容，直接换格式 |
| `state.vscdb.backup` | 只读展示，不处理 |
