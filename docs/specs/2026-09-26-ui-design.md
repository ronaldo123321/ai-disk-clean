# 子项目 2：界面设计

日期：2026-09-26
状态：已与用户逐节确认
依据：`2026-09-26-product-redesign-design.md` §3、§4.4、§8；`../plans/2026-09-26-engine-rebuild-plan.md`「不在本子项目内」中的「子项目 2 必须处理」
范围：菜单栏弹窗、主窗口方案页、确认单、执行进度、结果页、恢复区；以及界面依赖的引擎补充。每日扫描与自动清理（子项目 3）、自定义规则与匿名反馈（子项目 4）不在本范围。

## 1. 已确认的决定

| 问题 | 决定 |
|---|---|
| 「一键清理」后是否再确认 | 弹出确认单，写明不可还原项、移入恢复区的项和需要退出的应用；用户点「开始清理」才执行 |
| 确认、进度、结果在哪里显示 | 全部在主窗口。弹窗只负责「看一眼、点一下」（弹窗失去焦点会自动关闭，退出应用时焦点会被抢走） |
| 恢复区还原粒度 | 可以按「项」还原，也可以整批还原 |
| 实现方式 | 重写界面，沿用 AppKit `NSStatusItem` + 弹窗 + `NSWindow` 承载 SwiftUI；不用 `MenuBarExtra`（此前在 macOS 26 上图标不显示） |

## 2. 结构

### 2.1 界面层（`Sources/DiskCleanerApp/`，全部重写）

- **外壳**：`AppDelegate` 创建菜单栏图标、弹窗（`NSPopover` + SwiftUI）和主窗口（`NSWindow` + SwiftUI）。
- **AppModel**：唯一的界面状态，`@MainActor` 的 `ObservableObject`。阶段：
  - `idle`：尚未扫描
  - `scanning(step, cancellable)`
  - `ready(ScanResult, CleanPlan)`：方案可编辑勾选
  - `confirming(ConfirmationSummary)`
  - `executing(progress)`：含等待用户对某个应用做「强制退出 / 跳过」的子状态
  - `finished(RunReport)`
  - 恢复区列表独立维护，可随时刷新。
- **EngineService**：把扫描、退出应用、执行、还原、清空放到后台队列；进度经回调切回主线程；持有 `OperationCancellation`。
- 旧界面的 5 个文件（`AppState`、`ContentView`、`ConfirmViews`、`Engine`、`RingIcon`）、旧引擎（`Scanner`、`Planner`、`Executor`、`Quarantine`、`V2Policy`、`Evidence` 等）与对应旧测试在本子项目中删除。`dclean` 已只使用新引擎。删除前逐个确认不再被引用；`V2Paths` 仍被 `OperationLease`、`ProtectedLocations` 使用，保留。

### 2.2 引擎补充

1. **进度与取消**
   - `DetectContext` 增加可选的 `cancellation: OperationCancellation?`。`ProjectArtifactDetector`、`Sizer`、`SpaceMapDetector` 的遍历在每个目录处检查取消；Docker 探测之间检查取消。
   - `EngineScanner.scan(onStep:)` 在每个阶段开始时回调（规则、项目、Docker、估算、空间分布、占用检查）。取消时返回已完成部分并标记 `cancelled`。
   - `PlanExecutor.run` 增加 `onItemStart` / `onItemFinish` 回调，以及基于 `OperationCancellation` 的「停止」：当前项做完后不再开始新项，已完成的不回退。
2. **可交互的退出应用**
   - 新增 `PlanExecutor.quitPhase(items:consentedApps:) -> [QuitApp]`：对会执行的项所需的、用户同意代为退出的应用逐个正常退出，写审计，返回 10 秒内没退出的应用。
   - 界面对每个未退出的应用询问「强制退出」或「跳过相关项」，再调用 `forceQuit(apps:)`（写审计）。
   - 界面不经由 `run` 退出应用（传入的 `ExecutionOptions` 不含任何应用）；`run` 按 `options` 退出应用的旧方式保留给命令行使用。未退出的应用会让相关项按现有规则跳过。
3. **结构化原因**：`RunOutcome.skipped` / `.failed` 改为携带 `reason: OutcomeReason`（`appRunning`、`occupied`、`unavailable`、`gone`、`protected`、`auditFailed`、`commandFailed`、`recoveryFailed`、`cancelled`、`other`）和说明文字。
4. **按项还原**：`RecoveryEntry` 增加 `itemID`、`itemTitle`；`RecoveryStore.restore(batchID:itemIDs:)`，`itemIDs` 为 nil 表示整批；指定的项一个都匹配不上时返回错误；没有记录所属项的条目只能整批还原。批次展示按项聚合。
5. **打包后的规则读取**：`RulePack.bundledData()` 先在 `Bundle.main.resourceURL/DiskCleaner_CleanerCore.bundle` 中查找 `RulePack.json`，再找 `Bundle.main.bundleURL`（命令行程序）；只有 DEBUG 构建才兜底用 `Bundle.module`；都没有时返回 nil（调用方报错，不崩溃）。

### 2.3 数据新鲜度

- 确认单基于内存中的扫描结果生成；扫描结果超过 10 分钟时，先重新扫描再弹出确认单。
- 只执行本进程刚扫描得到的项，不持久化、不解码执行 `CleanItem`。
- 弹出确认单前重新检查需要退出的应用（`CleanPlan.appsToQuit` 只是扫描时的快照）。

## 3. 页面

### 3.1 菜单栏弹窗

- 磁盘已用 / 可用、上次扫描时间
- 推荐方案卡片：可腾出多少、各档项数、需退出的应用
- 「一键清理」：打开主窗口并直接弹出确认单（使用默认方案）
- 「查看详情」：打开主窗口方案页
- 恢复区占用
- 未扫描或扫描中：卡片处显示「正在扫描…（当前步骤）」与取消按钮
- 执行中：显示「正在清理 x / n」，点击打开主窗口

### 3.2 主窗口方案页

- 顶部：磁盘总览、上次扫描时间、「重新扫描」、按档位 / 按应用切换、右上角恢复区入口
- 每项一行：勾选框、名称、预计可释放、标记（需先退出 X、被占用、无法读取）、备注（如「闲置 214 天」）
- 展开：是什么、删了有什么影响、会不会自动长回来、路径列表（每条可「在 Finder 中显示」）
- 勾选：默认按 `PlanBuilder`；「只展示」无勾选框；「需要确认」默认不勾
- 「只展示」组中的未识别大目录只有「在 Finder 中显示」
- 底部固定：「清理已选 X GB」→ 确认单

### 3.3 确认单

- 标题：将清理 N 项，预计腾出约 X GB
- 移入恢复区（7 天内可还原）：项数、大小、项名
- 不可还原（工具自带命令）：橙色，项数、大小、项名及命令
- 需要先退出：可代为退出的应用带勾选（默认勾）；IDE、编辑器、Claude 等标为「请你保存后自己退出，不退出则相关项跳过」
- 「取消」/「开始清理」

### 3.4 执行中

- 进度条与「x / n」
- 逐项状态：等待、进行中（附当前步骤，如「正在退出 Chrome」「正在暂停 xxx 服务」）、完成、跳过、失败
- 应用 10 秒内未退出：显示「强制退出 X」/「跳过 X 相关的 N 项」
- 「停止」：当前项完成后停止，已完成的不回退
- 执行中关闭主窗口：后台继续，菜单栏图标显示进度，重新打开可继续查看

### 3.5 结果页

- 实际腾出（执行前后可用空间差）
- 恢复区中新增多少、到期时间，入口「查看恢复区」
- 跳过项与原因（按原因分组）；失败项与原因
- 会自动长回来的项及说明
- 服务未自动恢复的提示与手动命令
- 实际腾出与预估差距较大（小于预估的一半）时，提示可能原因：其他程序在写入磁盘、命令实际清理量小于目录大小、共享文件未释放
- 「完成」回到方案页并自动重新扫描

### 3.6 恢复区

- 总占用、保留天数、「清空已到期」
- 按批次分组，显示时间、大小、剩余天数；批次内按项列出，每项「还原」，批次「全部还原」「立即永久清空此批」
- 永久清空需二次确认
- 记录损坏的批次单独列出，说明「不计入、不会自动清空」
- 还原失败（原位置已有内容、副本已变化等）逐条显示原因

## 4. 错误处理

- 扫描出错不中断；读不到的目录在对应项上标注
- 执行出错只影响该项，原因显示在结果页
- 已有清理任务在运行（锁被占用）：提示「已有清理在进行」
- 审计日志无法写入：执行停止，结果页说明原因
- 内置规则读取失败：主窗口显示错误，不崩溃

## 5. 测试

- AppModel 用假 EngineService 单测：各阶段切换、扫描取消、扫描超过 10 分钟后重新扫描、退出应用超时后的选择、执行中停止
- 引擎新增能力沿用子项目 1 的测试方式：进度回调、取消、结构化原因、按项还原、打包资源查找
- 界面人工验收：安装到本机，逐页检查
- 首次真机清理（需用户当场确认）：只清安全档中的一两项，再从恢复区按项还原，确认全流程

## 6. 安装

沿用 `Scripts/make-v2-app.sh`：应用名为「清理大师V2」，安装位置固定为 `~/Applications/清理大师V2.app`，bundle id 固定为 `io.github.ronaldo123321.diskcleaner`，此后更新会保留已授予的系统权限；从更早使用旧 bundle id 的版本升级时，需要重新授予一次。版本号升到 0.11.0。
