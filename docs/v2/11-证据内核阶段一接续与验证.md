## 相对原计划的必要修正

1. 陈旧度不是只能增强：touch、同步和其他写入可能改变修改时间，因此本次已实现逐候选年龄重采集，未延后至阶段二。占用检查后再核验一次；不提供 rulesProvider 的库调用也核验计划中的弱证据。
2. 规则里的 epoch 时间仅表示陈旧度采集需求，不是文件观测；实际候选日期必须现场采集，不能以占位时间授予执行资格。
3. 路径日期解析需要适配器明确选择。普通下载目录和诊断报告默认使用 mtime，不把任意祖先目录的数字误认为文件年龄。
4. 规则 JSON 的 evidence 是不可信输入。V2Policy 清空传入证据，防止受保护或未知规则借自填证据获得权限。
5. Playwright 在执行前复查安装完成标记。Puppeteer 仍保持原适配器的官方布局检查范围，不虚构独立安装标记或已核验的工具版本。
6. 资格评估器返回 nil 并由校验、计划和执行边界拒绝非法组合；它不是一个凭类型系统就使任意 PlanItem 无法构造的证明，安全依赖这些实际边界校验。
7. risk 暂留为动作选择和序列化兼容字段；旧 Report 颜色分组方法仅为兼容接口及旧统计测试保留，不再驱动生产 GUI、CLI、Planner、Executor 或命令授权。
8. 未执行原计划中的自动 git commit、真实用户目录 plan 对照和应用安装脚本。安装脚本会删除/替换已有应用，本次未运行。
