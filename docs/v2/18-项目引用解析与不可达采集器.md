# 阶段二：项目引用解析与不可达采集器

## 开发顺序调整

Claude 精确目录授权和执行/恢复链路尚未完成。本轮先实现独立的 Codex/Cursor 引用基础能力，不通过放宽 Claude 保护来制造进展。阶段二仍未整体交付。

## 新增能力

### ReferenceReachabilityCollector

新增 ReferenceProbe 与 RealReferenceProbe，区分目录、其他对象、ENOENT 确认缺失和其他 errno 错误。旧 attributesIfExist 的 nil 不用于证明项目消失。

采集器要求适配器提供明确的 expectedVolumeRoot：该卷必须在当前本地挂载列表中，引用必须位于该卷内；对 /Volumes 下的路径要求指定对应卷根，禁止退回根卷判断。逐级检查现存祖先，符号链接、文件、权限错误、I/O 错误或设备不一致时弃权。最后再次比较挂载列表、卷设备和目标缺失状态。

只支持可确认的本地卷；网络路径拒绝。复杂挂载映射/APFS 路径别名不匹配时保守弃权，不猜测设备归属。输入卷根必须由未来适配器正确提供；本轮没有实现自动猜测卷归属。

### ProjectReferenceParser

- Cursor：只读 folder 元数据，接受本地 file URL；拒绝远程 host、认证字段、端口、query、fragment 和 workspace 文件。
- Codex：仅接受第一条 session_meta JSON 的 payload.cwd，不从聊天正文寻找 cwd。
- 两种解析都要求规范绝对路径，拒绝 NUL、控制字符、父目录跳转和根路径；数据上限 64 KiB。
- URL 显式百分号解码后再检查，避免编码 NUL 绕过校验。
- 调用方仍需执行有界文件读取；本模块只解析传入 Data，不读取真实会话内容。

## 验证范围

19 项新增测试覆盖正常缺失、目录存在、权限/I/O/ENOTDIR/ELOOP、链接祖先、外接卷未挂载、设备切换、采集期间卸载、挂载查询失败、路径校验、项目恢复、真实 lstat 结果，以及元数据 URL/类型/大小/多行边界。

测试首次发现 file URL 的 %00 未被拒绝，修复为显式解码后验证，再运行全量回归。

## 明确未完成

没有将引用证据自动注入 Rule，也没有启用 Codex 孤儿会话或 Cursor 失效工作区清理。未来必须绑定候选元数据快照和已核验卷身份，并在计划、执行占用检查后重新采集；仅有该采集器不能授权清理。

Claude 候选的精确授权、活动引用完整性、执行/恢复链路仍待实现。未改动用户保护设置、规则文件或真实文件，未进行真实清理。

## 最终结果

全量测试 258 项，跳过 2 项，失败 0 项；Release 构建通过；差异格式检查通过。本轮不包含真实用户目录扫描或清理。
