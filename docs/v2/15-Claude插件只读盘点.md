# 阶段二：Claude 插件只读盘点

## 实现范围

新增 `ClaudePluginInventory` 和 CLI 命令 `dclean plugins [--json]`。命令不构造清理引擎、不创建规则文件、不生成 Plan、不执行清理。它只读取固定的 Claude 插件缓存目录结构及安装登记元数据，不读取插件源码或会话正文。

- 逐层限定 `cache/<marketplace>/<plugin>/<version>`，拒绝中间路径和叶目录符号链接。
- 按数字版本比较，同一插件、同一市场内比较，保留最新/等价版本。
- 不支持的版本格式仅展示，不能推断为旧版本。
- 单独记录 `.in_use` 标记，坏链接标记同样视为占用提示。
- 读取 version=2 的 installed_plugins.json，记录 `isReferencedByRegistry`。仍被安装登记引用的版本必须保留，即使其旁边存在较新版本。
- 登记缺失、未知格式或错误时引用状态为 unknown（nil），不能当作未引用。目录读取失败也返回不完整报告。
- 所有结果都是观察值，不是 Evidence、Rule 或执行授权。未改动 PathSafety 的 Claude 根目录保护。

## 安全边界与后续

没有 `.in_use` 标记、也不在当前安装登记内，不等于不存在活动进程或其他工作区引用。当前仅用于盘点，不能直接接入清理。

下一步仍需要实现精确候选授权、进程/安装引用校验、证据与对象身份绑定、执行时再次核验，以及恢复路径的对应安全策略。尚未启用 Claude/Codex/Cursor 的新清理规则。

## 本机只读观察

目录枚举发现 4 个插件、9 个版本目录。其中 claude-mem 有 6 个数字版本，最新为 13.25.1；其余插件各 1 个版本。安装登记指向 claude-mem 13.25.1。旧版本存在不代表现在可以安全清理。

本次只读数据保存在构建目录，本机路径信息未对外发送。测试使用内存夹具，覆盖数字排序、标记、未知版本、符号链接、缺失目录、版本族隔离、序列化、安装登记仍引用旧版本和未知登记格式。
