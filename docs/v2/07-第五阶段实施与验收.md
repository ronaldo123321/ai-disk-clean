# V2 0.7.0：第五轮实施与验收

2026-09-18，分支 `codex/cleaner-v2`。本记录更新 06 中对应的未完成项（路线图第 3 项「完善扫描体验」）；开发版仍不等于公开发行版。

## 本轮新增

- **扫描进度与取消**：`ScanProgress` 逐规则回调（当前序号 / 总数 / 规则名）。CLI `dclean scan --progress` 在 stderr 原位刷新；GUI 顶部实时显示「扫描中 [i/N] + 当前规则名」，扫描中可点「取消扫描」，取消后报告标记 `isComplete=false`，不能据此生成方案（既有行为，本轮覆盖到深层遍历）。
- **取消贯穿深层遍历**：此前取消只在规则入口检查，collectMatches / apparentSize 内部不响应——取消一棵大目录树仍要等它走完。现在逐目录检查，取消及时生效。
- **深层目录权限错误提示**：遍历中无法读取的目录不再静默跳过。ReportEntry 新增 `unreadableCount`（总数）与 `unreadableSamples`（最多 5 条样本）；扫描期间目录消失（ENOENT）视为正常波动不计入。根目录不可读维持既有 `.unavailable` 状态。CLI 表格与 GUI 行内均标注「N 个目录无法读取」。
- **跨规则去重（A10）**：同一候选路径被多条规则发现时，只登记给更早的规则（规则顺序确定性：遗留规则按文件序 + 适配器固定追加序），后续规则的条目标注 `duplicateCount`，候选清空，合计不重复计数。父子嵌套（同路径去重无法识别）仍由 Planner 的歧义范围拒绝兜底（防御纵深，既有测试更新覆盖两种语义）。
- **glob 深度剪枝**：不含 `**` 的 glob（如 `*.ips`）只下钻到声明深度，不再递归子树——降低频繁扫描的 I/O 开销；`**` glob 行为不变。
- **修复 compileGlob 语义 bug**：「`**/`」此前编译为 `.*\/`，要求中间至少一层目录，导致 `logs/**/*.ips` 漏掉第一层的 `logs/a.ips`。按标准 glob 语义改为「零或多层目录」（`(?:.*/)?`）。存量适配器 glob（pip/playwright 的根尾 `**`、诊断报告单层 `*`）不受影响，新增回归覆盖。
- **频繁扫描冷却**：GUI 60 秒内的重新扫描请求直接忽略（降低重复全量扫描的系统开销；引擎层不设限制）。

## 验证结果

- `swift test`：159 项，157 通过、2 跳过（真机门控）、0 失败。新增 7 项：进度回调顺序与总数、深层不可读目录样本、消失目录不计入、单层 glob 剪枝且不漏候选、`**/` 零层目录回归、跨规则去重（glob 与 allowlist 两种路径）、预取消标记不完整。
- `DCLEAN_SMOKE=1` 真机只读验证：完整 home 扫描 26.4s；五个适配器规则全部带证据产出。
- 真机 `dclean scan --progress`：17 条规则逐条显示进度，报告与 0.6.0 基线一致（uv 21.1G / brew 568.8M 绿色命令委托；playwright 4.0G / puppeteer 456.3M 黄色逐项）。
- GUI 变更（进度显示、行内标注、冷却）编译通过，沿用 0.5.0 已验收的数据流；本轮未重做原生界面验收，进度与标注的实机呈现待下一轮界面验收一并确认。

## 已知边界（更新）

- 深层权限提示仅覆盖「规则根可达但内部部分目录不可读」；根本身不可读仍走 `.unavailable`，两者 UI 呈现位置不同（后者在分类页不可见，仅 CLI/JSON 可见）——下一轮界面验收确认是否需要统一。
- 去重顺序依赖规则数组顺序；用户编辑 rules.json 调整顺序会改变去重归属（行为确定但可感知，界面已标注数量）。
- 其余边界（删除竞态、跨卷、版本升级）与 06 记录一致，未变化。
