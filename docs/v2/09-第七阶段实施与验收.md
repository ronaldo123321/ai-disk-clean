# V2 0.9.0：第七轮实施与验收

2026-09-18，分支 `codex/cleaner-v2`。本轮完成 A 项剩余三块：自动扫描、扫描性能、权限提示呈现统一；并补齐 PRD §4 的菜单栏状态。开发版仍不等于公开发行版。

## 本轮新增

- **自动扫描（用户可启用）**：设置页新增开关「自动扫描（每 24 小时，仅应用运行时）」，持久化到本地偏好；启用时立即补一次扫描，此后每 30 分钟检查一次、距上次成功扫描超 24 小时才触发。首次扫描仍由用户手动发起（PRD：首扫由用户点开始）。清理动作不受影响——任何清理仍需逐项确认。
- **菜单栏状态（PRD §4 补齐）**：状态项从「点击开窗」升级为状态菜单：可用空间 / 总容量、上次扫描时间（今天/昨天 + 时刻的短格式）、「打开主窗口」、「退出清理大师」。
- **扫描性能（并行化）**，真机 17 规则全量实测：
  - `scan`：23.4s → **7.7s**（3.0×）
  - `plan`（含扫描与计划预览）：32.3s → **10.6s**（3.0×）
  - 手段一：候选占用评估并行化——lsof 子进程是计划预览的主要耗时（每个约 0.3s），有界并发 4，结果按原序组装；
  - 手段二：`apparentSize` 并行 BFS——按层并发 stat（并发 8），大目录树（uv 缓存 21 GB）为最大收益来源；
  - 语义与串行版一致：du 口径、符号链接只计自身、目录消失不计错误、`unreadableSamples` 顺序可能因并发而变化（数量不变）；取消立即生效。
  - 线程安全配套：ScanCollector 与 FakeProcessRunner 加锁（并行守卫评估下必加）。
- **权限提示呈现统一**：根目录不可读（`.unavailable`）的条目现在在「暂不可处理」分类行内直接显示原因（此前原因仅在 CLI/JSON 可见）；与深层目录不可读的行内橙色标注风格一致。
- 状态文案更新：设置页「自动扫描和企业策略管理未启用」改为随开关状态变化的说明；企业策略管理仍未启用（属公司试用能力范围）。

## 验证结果

- `swift test`：160 项，158 通过、2 跳过（真机门控）、0 失败。并行化后全部既有尺寸/语义断言保持绿（等价性回归）。
- 真机计时对比（同机同负载）：如上，3.0× / 3.0×。
- 截屏验收：设置页开关与动态说明渲染正确；菜单栏图标（externaldrive）确认存在。
- 交互限制如实记录：状态菜单的「点击展开」无法用合成点击验证（发布进程无辅助功能授权），菜单项构建逻辑为标准 NSMenuDelegate 代码，实际展开效果待人工点一下确认。
