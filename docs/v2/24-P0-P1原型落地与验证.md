# P0 / P1 原型落地

日期：2026-10-14。基于已确认的 `docs/prototype/index.html`；只实现 P0/P1，不新增 P2 空间下钻、应用详情或历史恢复界面。原有恢复区继续保留。

## 已实现

- 原生 SwiftUI 项目清理 / 应用与缓存 / 扫描范围导航；项目父子选择、部分选择状态、路径搜索、体积/闲置时间/名称排序及风险过滤；详情侧栏展示依据、影响、路径和长期保留入口。跨视图选择在底部明确计数，确认单列出全部所选项。
- 立即释放估算仅包含原生命令项；恢复区移动独立显示表观占用。结果显示带方向的卷可用空间变化，明确它不是独立归因于本工具的释放量。菜单栏和 CLI 同步拆分文案；CLI JSON 增加 `estimatedImmediateBytes`、`recoveryMoveBytes`，保留旧汇总字段供兼容（不能将旧字段理解为立即释放）。
- 项目产物独立执行。扫描时验证 Git 跟踪内容、嵌套仓库、环境配置/常见密钥文件名、常见源码类型与工程标记。无法验证或命中保护时禁选；执行前复查证据及其 10 分钟有效期，变化则跳过。服务等待后再次复核；扫描目录身份传递到恢复区接纳及移动前检查。
- 项目目录、排除目录和长期保留通过本机 UserDefaults 持久化。范围更改使旧方案失效；保留操作取消对应选择，重扫不会自动选回。当前支持家目录内的工作目录，不扩展到外部卷。自定义项目范围时不运行原先全家目录的大目录盘点；应用缓存仍按规则检查。
- 扫描分阶段显示已发现条目，验证未完成前不允许清理。不可读目录、深度上限与部分计量单独报告。取消/失败不能让旧方案恢复为可执行状态。
- 确认单要求勾选理解不可撤销操作与恢复区占用的区别；编辑器仍由用户自行保存退出，未退出的项跳过。

## 已知边界

- 证据是目录元数据摘要（含 inode、尺寸、时间戳）、工程标记属性及源码活跃时间，不是全部文件内容哈希，也不是文件系统原子快照。恢复区保留原有移动前后身份/摘要复核；不能宣称消除了所有并发写入竞态。
- 敏感内容采用保守规则，不是任意语义的密钥检测；不能证明没有任意文件名的用户数据。构建目录含常见源码会保护，依赖目录中的依赖源码不据此误拦。
- 单项证据遍历最多 300,000 节点 / 15 秒（Git 只读查询另有超时），超限禁选；不会为完成扫描降低安全门槛。
- 共享数据块/硬链接使各产物估算之和不等于最终释放量。到期仅提醒，恢复区不会自动清空。
- 内部项目项 ID 从 `project:<root>` 拆为 `artifact:<path>`；旧恢复批次继续按原 ID 恢复，新 CLI `--only` 应使用新扫描输出的产物 ID。
- 原型的 P2 独立空间浏览和历史恢复新版暂未实现，符合本轮范围。
