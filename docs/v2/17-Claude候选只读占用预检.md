# 阶段二：Claude 候选只读占用预检

## 实现

新增 ClaudePluginPreflight 与 `dclean plugins --preflight [--json]`，复用候选预览和现有 GuardEvaluator。没有候选或预览不完整时不启动进程查询。

存在候选时使用固定参数查询已知 `claude` / `Claude` 进程，已发现进程或无法确认进程状态时不继续目录探测。已知进程均未发现时，检查候选快照，然后使用 lsof 递归检查候选目录。

状态包括 clear、blocked、unknown、stale。子进程无法启动、错误输出或不合预期的响应不能当作空闲。检查后重新盘点，比较安装登记摘要、候选、新版本身份、标记和保护位置；计算经过的单调时钟时长用于 15 分钟时效检查。

clear 仅代表这次查询未发现占用，不代表全体工作区/子进程均无引用，更不代表获得执行授权。Report 的 executable 始终 false；PathSafety 的 Claude 整树保护不变，尚无 Claude 新规则进入生产执行计划。

## 测试

新增 9 项内存测试：固定命令参数、检查通过仍不可执行、Claude 运行、pgrep 无法启动、lsof 无法启动、目录被占用、检查期间出现 .in_use、无候选不查询、登记错误不查询以及错误输出不能视为空闲（部分场景合并于同一测试）。

## 尚未完成

精确作用域授权、完整的执行/恢复链路、其他进程和项目引用论证，仍未完成。本机旧插件已有 .in_use 标记，不会为构造可清理候选而移除这些标记。该预检模块是基础工作，不代表阶段二交付完成。
