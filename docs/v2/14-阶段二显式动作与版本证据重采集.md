# 阶段二：显式动作与版本证据重采集

2026-09-19

## 本次实现

- Rule 新增可序列化的 `actionIntent`。显式动作优先，旧规则没有该字段时仍按原逻辑兼容；没有删除旧 JSON 的 risk 字段。
- 五个已验证适配器及诊断报告、旧磁盘映像规则显式声明动作。文件项仍移入废纸篓，uv/Homebrew 仍执行原命令，不改变清理范围。
- V2Policy 丢弃外部规则自填的动作意图与证据，然后为已知规则重新建立动作与依据；不能利用 JSON 自声明获得额外权限。
- validateRules、Planner 和带规则提供器的 Executor 拒绝动作与策略不一致、命令参数不一致的规则。弱证据不可用于不可逆动作的不变量仍被执行。
- 版本冗余证据接入 `Rule.collectedEvidence`：不再把声明当作实际观测，验证候选版本和版本族归属并现场重新采集。
- 执行器在占用检查后再次核验版本证据，避免检查过程中出现 `.in_use` 标记仍继续执行；无 rulesProvider 的库测试路径也做此检查。
- 新增 8 项动作意图测试、5 项版本证据流水线测试。本次未撤销 Claude 插件根目录或 Codex 会话保护，未新增生产可执行规则。

## 接续边界

Claude 插件适配器仍未接入，因为当前 PathSafety 将整个 `.claude/plugins` 树设为保护范围。不能简单删掉该保护；需要为核验过的旧版本建立精确作用域授权，并使扫描、计划、执行及恢复都使用同一授权边界。

引用不可达采集器仍待实现。必须先区分路径确实不存在与权限不足/读错误，并确认卷已挂载，不能把 `attributesIfExist == nil` 当作孤儿证据。

本次是阶段二中间里程碑，不代表 Claude/Codex/Cursor 新规则已交付。
