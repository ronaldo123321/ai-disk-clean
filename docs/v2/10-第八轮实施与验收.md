# V2 0.10.0：第八轮实施与验收

2026-09-18，分支 `codex/cleaner-v2`。本轮响应用户对设计的直接反馈（「直接放入本地的废纸篓就行，这里也能恢复，恢复中心多此一举」），重构清理项的存储目的地；并修复目录候选选中后按钮永久禁用的真 bug。开发版仍不等于公开发行版。

## 修复（用户实测发现）

- **目录候选选中后「移到废纸篓 0 B」、处理方案按钮永久禁用**：选中统计对每个候选重新 stat 其 inode 的 allocatedSize——文件候选正确，目录候选（Playwright/Puppeteer）在 APFS 上目录项自身块数≈0。0.5.0 验收时只有 pip 文件规则未暴露，0.6.0 引入目录规则后咬人。
- 修复：扫描时记录逐候选大小（candidateSizes，目录为内容 du 口径），统计改用 includedBytes(excluded:)，不再事后 stat；旧报告向后兼容（无排除用整条大小，有排除按比例估算）；详情页逐候选显示大小。回归测试锁死。

## 设计修订：黄色项移入系统废纸篓（用户决策）

- 存储：`~/.Trash`（同卷改名，语义与原先隔离区一致——移入不释放空间）。
- 还原：仍经恢复中心页（或 CLI restore），保留身份快照、目录内容清单（防部分删除副本被静默还原）、还原目标围栏复核、write-ahead 移动日志。
- 取消：30 天保留期、到期提醒、本工具内「永久清除」/「再保留 30 天」/CLI purge——废纸篓的清倒即永久删除，由用户在访达自行控制。
- 概览页的「到期批次」横幅随之移除（无到期概念）。
- 授权提示：首次移入时 macOS 可能弹一次废纸篓访问授权（GUI）；CLI 需要 FDA 或终端的废纸篓访问授权——CLI 在无授权时报错已改善为明确的权限提示（此前误报为「符号链接」）。
- 记录（manifest）作为旁路文件存于 `~/.dclean-v2/recovery/`，不随清倒消失；副本被清倒后还原会如实报告「副本已不在废纸篓」。

## 验证结果

- `swift test`：152 项，150 通过、2 跳过（真机门控）、0 失败。10 个 purge/到期/批次目录用例随语义删除或改写；中断续作、防篡改、目录清单等安全用例全部适配并保持。
- 真机 CLI 端到端：夹具文件经 plan → apply 尝试移入废纸篓，被 TCC 权限拦截（预期，见上）；错误信息已改善。GUI 路径的废纸篓授权弹窗与实际移入待用户首清时确认。
- 全部文案统一为「移到废纸篓（清倒前可还原）」。
