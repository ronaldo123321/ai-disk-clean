# 阶段二：Codex 会话首条元数据只读盘点

## 实现

新增 CodexSessionInventory 和 `dclean sessions [--json]`。固定遍历 `.codex/sessions` 的日期目录，不跟随链接，限定目录深度与扫描条目上限。只处理 rollout-*.jsonl，报告是不可执行观察，不生成 Rule 或 Plan。

新增 BoundedMetadataReader.firstLine：生产使用无链接父目录句柄和 openat 打开普通文件，逐字节读取直到第一个换行或 EOF，首条记录最多 64 KiB，不读取之后的聊天正文；即使会话文件整体很大也无需读全文件。读取前后核对身份、大小、修改时间，活跃写入导致不一致时弃权。

解析仅接受 session_meta 的 payload.cwd；首条不符合要求时不继续搜索后续记录。年龄依据严格截取 sessions 后的 YYYY/MM/DD 三层相对路径，避免误用更上层目录日期；无合法编码日期时回退修改时间并记录来源。

项目引用状态和年龄独立记录：项目存在、确认缺失、无法确认；是否超过 90 天并不等于是否可删除。引用缺失要经过本地卷挂载、设备与祖先检查。报告始终 executable=false。session 元数据或文件身份在观察期间变化时，降为未知。

## 本机只读结果

- 482 个会话文件，报告完整。
- 481 个引用的项目目录存在。
- 1 个通过本地卷及路径核验后，观察到引用项目缺失。
- 109 个会话目录日期超过 90 天；全部 482 项日期来源为 pathEncoded。
- 项目缺失与年龄是不同维度，不相加计算清理数量或可释放空间。
- 未改写用户会话、规则或保护设置，未生成清理计划。报告仅保留本地构建目录，未发送会话数据到外部服务。

## 测试与构建

新增 8 项测试：年龄与引用独立、项目缺失不授予权限、外接卷未挂载、仅首条元数据、扫描上限、链接拒绝与核心保护保持、首行大小上限独立于正文大小，以及真实临时夹具的有界首行读取。

全量测试 277 项，跳过 2 项，失败 0 项。Release 构建通过，差异格式检查通过。

## 阶段二交付缺口

截至本轮，Claude 插件、Cursor 工作区和 Codex 会话已有独立只读观察模块，但阶段二的新增可执行清理规则**尚未交付**。

剩余关键工作是精确作用域授权、适配器与现有 Scanner/Planner/Executor 接合、占用和元数据快照复核、恢复路径一致性、临时目录完整清理/还原闭环，以及 GUI 展示。不能将辅助 CLI 的只读盘点视作这些工作已经完成。

已知本机 Claude 5 个旧版本均带 .in_use 标记，仍保留；Codex 的 1 个缺失项目引用与 109 个旧会话也不能绕过会话保护直接执行。
