# 子项目 2：界面真机验收

2026-09-27｜对应计划 `docs/plans/2026-09-26-ui-plan.md` Task 14｜本轮由用户在界面中逐次确认并操作，Claude 只读核对审计日志、恢复区与文件状态。

## 实现

界面重写为菜单栏弹窗 + 主窗口，全部基于新引擎：

- 菜单栏图标显示磁盘已用比例；弹窗展示推荐方案、「一键清理」「查看详情」、恢复区占用、扫描与执行进度。
- 主窗口方案页按档位或按应用查看，每项可展开说明与路径；「清理已选」弹出确认单，分列移入恢复区、不可还原（附命令）、需要先退出的应用。
- 执行页列出全部项及状态（等待 / 进行中 / 完成 / 跳过 / 失败），显示「正在退出 X」「正在暂停 X 服务」等分步提示；应用 10 秒内未退出时逐个选择「强制退出」或「跳过相关的 N 项」；可随时停止。
- 结果页按清理前后可用空间报告实际腾出，列出跳过与失败原因、会自动长回来的项。
- 恢复区按批次、按项还原；永久清空需二次确认。
- 引擎补充：扫描与执行的进度回调和取消、可交互的退出应用阶段、结构化跳过原因、按项还原、安装包内规则查找。
- 旧界面、旧引擎及其测试已删除。

## 发现与处理

1. **永久清空不写审计日志（已修复）。** 07:49 的永久清空在审计中没有任何记录。改为删除前必须写入 `purge.intent`，写不进去就不删；删除后写 `purge.done`。界面与命令行都已接入。
2. **命令类清理项不进恢复区（符合设计，验收用例选错）。** npm 缓存由工具自带命令清理，属于「不可还原」，确认单中以橙色列出。按项还原的验收改用会移入恢复区的项目产物与应用缓存。
3. **移入恢复区不腾出空间（符合设计）。** 同卷移动，结果页「已腾出」为 0；审计中的少量负值来自清理期间其他程序写入磁盘，界面按 0 显示。空间在恢复区到期清空或手动永久清空后释放。
4. **还原暂不写审计日志（用户决定暂缓）。** 本轮对还原的核对依据文件状态与恢复区目录，README 已注明。

## 整体代码审查

对子项目 2 全部改动做了一次整体审查，无严重问题，以下问题均已修复并复审通过：

- 清理完成后取消或未完成的重新扫描，会让清理前的扫描结果重新可确认，命令项可能被再次执行。改为清理完成后必须完成一次新的扫描才能确认。
- 安装包缺少规则资源时，SwiftPM 的 `Bundle.module` 会直接终止进程，且会读取开发目录。改为只在应用包与可执行文件目录中查找，找不到返回「找不到内置规则」；`Bundle.module` 仅在调试构建中兜底。
- 执行中可以退出应用，可能使被暂停的服务停留在暂停状态。改为执行中拒绝退出并提示先停止。
- 退出应用阶段点「停止」后仍会继续退出后面的应用。改为每个应用前检查停止；面板出现前后按停止都不会强制退出。
- 执行页补齐全部项状态、分步提示和逐个应用的选择；恢复区操作进行中时互相拦截，并拦截扫描、清理与「完成」；命令项审计不再记 0 字节；删除旧引擎遗留的无用代码与过时注释；主窗口标题改为「清理大师V2」。
